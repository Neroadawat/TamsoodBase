## ประเด็นที่ตรวจพบ

**น้ำปี 2024:** ตารางเนื้อหารายงานน้ำใช้ 3,044,250 m3/year ขณะที่ภาคผนวกรายงานน้ำถอนจากแหล่ง 3.06 ล้าน m3 อีกคู่คือน้ำดิบภายนอกกับน้ำจืดให้ตัวเลขเดียวกันตามสองตารางนี้

ช่วงตัวเลขที่การปัดเศษแบบ nearest อธิบายได้ไม่ทับกัน แต่ชื่อรายการ หน่วยแสดง และบริบทต่างกัน จึงตั้งสถานะ HOLD_CONTEXT_OR_REVISION_DIFFERENCE เก็บทั้งสองคู่ ไม่ประกาศว่ารายงานผิด ไม่เลือกค่าฝ่ายใด และไม่ถือว่าเป็น duplicate ที่ยืนยันแล้ว

ตัวเลขน้ำใช้ปี 2022/2023 อยู่ในช่วงที่การปัดเศษอธิบายได้เมื่อเทียบกับเลขในภาคผนวก แต่ก็ไม่ได้พิสูจน์ว่านิยามตรงกัน

**ยอดพลังงาน:** ตรวจ total energy เทียบ fuel + electricity purchased และตรวจ fuel เทียบ gas/LPG/fuel gas/coke รวม 8 กรณีในปี 2021–2024 ทุกกรณีอยู่ใน tolerance ของเลขทศนิยมที่แสดง โดยคำนวณ tolerance จากครึ่งหนึ่งของหลักสุดท้ายของแต่ละตัวที่ร่วมสมการ คงค่าเดิมทั้งหมด ไม่แก้ยอดรวมให้ตรงกันและไม่ใช้ผลนี้แทนการตรวจความถูกต้องทั้งชุด

**หน่วยและตัวหาร:** ความเข้มเชื้อเพลิง GJ/t throughput เก็บเป็น reported intensity แยกจาก annual energy ไม่ย้อนหาปริมาณ throughput จากค่าที่ปัดเศษ ไม่ตีความเป็น LCI ต่อผลิตภัณฑ์ และไม่จัดสรรให้เชื้อเพลิงแต่ละชนิด

## รันซ้ำ

```powershell
python -X utf8 scripts/acquire_thaioil.py --source sprc
python -X utf8 -m src.sprc_report
python -X utf8 scripts/mysql_workspace.py load --reports
python -m unittest discover -s tests -v
```

ชื่อ acquisition script เป็นชื่อเดิม แต่มี --source เลือกสอง publisher จาก URL ทางการที่กำหนดไว้ ตัว extractor ต้องใช้ Python ที่มี pypdf==6.10.0 เหมือนตัวอย่างไทยออยล์

ผลอยู่ build/sprc-report/: รายงาน JSON, SQLite, SQL, ผลเทียบ Decimal/metadata จาก MySQL และข้อความหน้า PDF สำหรับตรวจซ้ำ raw PDF คงอยู่ local และไม่เข้า Git เพราะยังไม่ยืนยันสิทธิแจกจ่ายซ้ำ

หน้าเว็บเลือก “ข้อมูลจากรายงาน” → “SPRC” → ปี 2024 เพื่อดู issue สองคู่และเปิดต้นทางแต่ละรายการ ข้อมูลชั้น staging คง PENDING_DOMAIN_AND_RIGHTS_REVIEW; ชุด reference ที่ทีมคัดแล้วดูเมนู “พร้อมใช้ต่อ” และ reusable-model.md โดยแยกจาก normalized product LCI ซึ่งยังเป็น 0

## ผลต่อการออกแบบ

metric identity ต้องรวม source document/version และปี พร้อมแยกชื่อรายการและตำแหน่งต้นฉบับ ห้ามรวม “water used” กับ “water withdrawn” เพียงเพราะคำแปลใกล้กัน

ตาราง report_metric ปัจจุบันเป็นชั้น staging สำหรับเก็บค่าและ payload จากเอกสาร ไม่ใช่ canonical relational inventory ที่อนุมัติแล้ว การออกแบบ process/exchange ต้องรอขอบเขตจริงและกฎ mapping ที่มีหลักฐาน
