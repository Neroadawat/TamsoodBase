manifest ที่ตรึง hash ป้องกันการแก้ไฟล์สกัดโดยพลการเมื่อคง manifest ตามรุ่น การอนุมัติรุ่นใหม่ต้องมีผู้ทวนแถวต้นทางและบันทึกเหตุผล เพราะผู้ที่แก้ได้ทั้งข้อมูลและ manifest ยังสามารถออก hash ใหม่ได้

ตรวจ Python 247 รายการผ่าน การเปลี่ยนแถวมวลทำให้ผลขนส่งเปลี่ยนตามสูตร และการแก้ไฟล์สกัดนอก manifest ถูกปฏิเสธ ตรวจเว็บ local ด้วย Chrome ที่ 390 และ 1440 px ครอบคลุมลิงก์ตรง โหลดซ้ำ เลือกด้วยคีย์บอร์ด ย้อนกลับ และหน้าไม่ล้น ตรวจ export กับฐาน local โดยคำขอไม่กรองถูกปฏิเสธ ส่วนปี 2024 ได้ 1,125 แถว


## ผลตรวจปิดเกณฑ์วิศวกรรม T138

- สร้างรายงานเอทานอลจากไฟล์ที่ระบุ 10 ไฟล์ในโฟลเดอร์ชั่วคราว ผลตรงรายงานที่บันทึกไว้ทุกไบต์ การทดสอบนี้ใช้หลักฐานที่ตรึงไว้ในเครื่อง ส่วนการจัดหาชุดวิจัยจาก clean checkout ยังต้องจัดการไฟล์ที่มีข้อจำกัดสิทธิ
- ลงทะเบียน DEDE, มช., TSM และ UASB ใน SQLite ตาม hash ของไฟล์หลักฐาน พร้อมสถานะ DRAFT และ NOT_CLEARED ใช้ขั้นตอนตรวจทานที่มีอยู่ ตรวจจากสำเนาในหน่วยความจำว่าแก้ข้อมูลรุ่นเดิมไม่ได้และบัญชีงานภายในไม่สามารถเปลี่ยนเป็น PUBLISHED เหตุการณ์อนุมัติจริงในฐานมีศูนย์รายการ
- ตรวจ build หน้าเว็บในโฟลเดอร์แยกจากรายการอนุญาต 17 ไฟล์ และตรวจ hash ของ asset 14 ไฟล์
- ตรวจ proxy ด้วยการจำลอง upstream ที่ค้างจนหมดเวลา ได้ HTTP 504 และยกเลิกคำขอต้นทาง ตรวจการยกเลิกเมื่อ client ตัดการเชื่อมต่อด้วย ผลนี้เป็นการจำลองในเครื่อง การวัดภายใต้โหลดจริงยังค้าง

หลักฐานอยู่ใน evidence/ethanol-release-verification.json และ evidence/frontend-cleanroom.json เกณฑ์ที่ยังเปิดคือผู้ทวนและสิทธิจริง การทดสอบกับผู้ใช้และ screen reader การวัดโหลดและแผนคิวรี production ปลายทางถาวรและการเผยแพร่ รวมถึงข้อมูลวิทยาศาสตร์ในตารางเดิม

## การทวนภายในโดย Codex

ผู้ใช้อนุญาตให้ Codex ทวนงานของตัวเอง ตรวจไฟล์หลักฐานกับข้อมูลที่เก็บตาม hash ในทะเบียนครบ 4 กรณี อนุมัติการใช้ภายในตามขอบเขตของแต่ละกรณีใน evidence/ethanol-internal-self-review.json การอนุมัติครั้งนี้แยกจากการทวนอิสระและสถานะการเผยแพร่ในทะเบียน สิทธิแจกจ่ายยังอยู่ที่ NOT_CLEARED และยอด CO₂e ทั้งวงจรยังเป็น null
