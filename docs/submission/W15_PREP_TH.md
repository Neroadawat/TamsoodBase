## ความเสี่ยงที่ต้องตัดสินใจก่อนวันจันทร์

1. **หน้าข้อมูลบนเว็บจริงปิดอยู่** ทุก route ข้อมูล (`/api/summary`, `/api/nso`, `/api/eppo`, `/api/records` ฯลฯ) ตอบ 403 ตั้งแต่ 10 พ.ย. ผู้ชมและกรรมการเปิดดูแถวข้อมูลหรือย้อนต้นทางบนเว็บไม่ได้ ซึ่งเป็นขั้นที่ 2, 6, 7 ของการนำเสนอ backend บน EC2 ยังตอบปกติ (`/readyz` = ready ณ 13 พ.ย.) มีแพตช์เปิดคืนเฉพาะข้อมูลรัฐและบทความ โดยยังปิดปริมาณของรายงานบริษัท รออยู่ในเครื่อง ยังไม่ได้ commit/deploy เพราะต้องให้เจ้าของโครงการสั่งเอง
2. **จำนวน Accepted tuples** ต้องให้ทีมตัดสินใจและบันทึกกฎรับข้อมูลสำหรับสถิติรัฐ (เช่น ผ่าน A05 traceable + A07 constraints + A08 unique = `ACCEPTED_SOURCE_STATISTIC`) แล้วเลื่อนสถานะด้วยหลักฐาน ไม่ใช่เปลี่ยนป้ายเฉย ๆ ตอนนี้ schema ล็อก `review_status='PENDING'` ด้วย CHECK ต้องแก้ DDL ด้วย
3. **Backend พึ่ง Cloudflare Quick Tunnel** ถ้า EC2 หรือ tunnel รีสตาร์ต URL จะเปลี่ยนและเว็บจะดึงข้อมูลไม่ได้ ต้องมีแผนสำรอง: เปิด explorer ในเครื่อง (`python -X utf8 src/explorer.py`) หรือภาพหน้าจอ/วิดีโอสั้นของขั้นที่ 7
4. **"Demo รันได้บนเครื่องในห้อง"** เครื่องบนโพเดียมเป็นของห้อง ไม่มี Docker/MySQL ของเรา ต้องเดโมผ่านเว็บ หรือขอใช้เครื่องตัวเอง ควรถามอาจารย์
