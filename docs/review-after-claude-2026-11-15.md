## จุดให้ Claude แก้ต่อในไฟล์ที่ตัวเองดูแล (ไม่ต้องสร้างชุดใหม่)

1. **สไลด์ 5 อ้างฉากคลิปผิดแถว**
   - `output/m4/slides-source/build_slides_3min.js` ข้อความ “ต่อจากนี้: บรรทัด 11399 ... (ดูในคลิปฉาก 4)” ไม่ตรงคลิปจริง
   - ตรวจเฟรมวินาที 53 ของ annotated: ฉาก 4 แสดงเอราวัณ น้ำมันดิบ ธ.ค.2024 ค่า0 บรรทัด11202 ไม่ใช่เบญจมาศ มี.ค.2026 บรรทัด11399
   - แก้ง่าย: “ตัวอย่าง SQL: เบญจมาศ บรรทัด 11399 · ในคลิปสาธิตวิธีย้อนที่มาด้วยแถวเอราวัณ 11202” หรือเลิกอ้างว่าคลิปแสดงแถวเดียวกัน ไม่ต้องตัดคลิปใหม่
   - สไลด์1/โปสเตอร์ยกไพลินเหนือ11394เป็นอีกตัวอย่าง ไม่ผิดเอง แต่ผู้พูดต้องบอกว่าเป็นคนละตัวอย่าง

2. **อย่าใช้คำว่า Rejected/ไม่รับ แทน243ทั้งก้อน**
   - แก้สไลด์6/10 และโปสเตอร์3/9 เป็น “ยังไม่รวมในยอดรับ 243 รายการ” หรือ “แยกออก/พักตรวจ 243 รายการ”
   - DMF238 = โครงสร้างผิด6 + สำเนา42 + ขัดกัน186 + พักหน่วย3 + พักขนาด1 อีก5อยู่ชุดอื่น
   - PENDING228ในฐาน = สำเนา42+ขัดกัน186 ไม่เท่ากับ REJECTED228; ห้ามแก้สถานะเพื่อให้ตรงคำย่อบนสไลด์

3. **ERD ฉบับย่อควรให้ลูกศรตรง FK จริง**
   - แผนภาพสไลด์4 มี resource_snapshot → observation ลงมาตรงกลาง และ observation → duplicate_disposition แต่ไม่เห็น source_record → observation ตาม composite FK ที่ข้อความอธิบาย
   - ให้แสดงเส้น source_record → observation กับ source_record → rejected_record ชัด และระบุความหมาย/คาร์ดินาลิตีของเส้น ภาพเป็นสรุป ไม่จำเป็นต้องวาด ER ของเพื่อนใหม่
   - publisher/product เป็นอีก2ตารางที่ไม่ได้วาด: ใช้คำว่า “แสดง7จาก9ตาราง” หรือระบุว่าภาพย่อ

4. **SQL กับ Cypher ต้องบอกขอบเขตหลักฐานให้ตรง**
   - การเทียบ SQL เดิมใน evidence/neo4j-inventory-audit.json เป็น SQLite (`equal_to_sqlite`) ไม่ใช่การรัน MySQL Q1–Q2 ล่าสุด
   - รอบนี้เพิ่มผลจริง CSV32columns→Neo4j และ API parity แล้ว แต่ยังไม่ยืนยันว่า SQL ที่พิมพ์บนโปสเตอร์รันผ่าน MySQLจริง
   - ถ้ายังรันไม่ได้ ให้หัวตารางคง “SQL สำหรับ MySQL” แต่หมายเหตุว่า “ผลเดิมเทียบ SQLite และยืนยันกับ API/CSV/Neo4j; ยังไม่รัน query นี้กับ MySQL รอบล่าสุด” ห้ามอ้างว่าผ่านครบจาก APIอย่างเดียว
   - คำสั่ง Q1 JOIN และชื่อคอลัมน์ตรง supplemental-schema.sql ในเครื่อง; Q3 ยังเป็นตัวอย่าง ไม่ใช่ผลทดลอง
   - บล็อก LOAD CSV มี `…row.process` และ flow ที่ย่อออก เป็นโค้ดอธิบาย ให้ติดป้าย “ตัวอย่างย่อ ไม่ใช่คำสั่งพร้อมรัน” และชี้ไป scripts/load_product_inventory_csv.cypher

5. **deduplicated_pending ไม่ได้กรอง Accepted โดยนิยาม**
   - view ใน full-schema.sql กรองเพียง SINGLETON/EXACT_REPRESENTATIVE จึงยังอาจรวม unit/magnitude holds ชื่อ pending เป็นชื่อ legacy
   - 4แถวในตัวอย่างนี้ accepted จริงจาก API แต่ห้ามอธิบายว่า view ทั้งหมดเป็น Accepted-only
   - หากต้องการสาธิต accepted-only ให้เพิ่ม WHERE review_status='ACCEPTED_SOURCE_STATISTIC' และรันยืนยันอีกครั้ง ไม่เปลี่ยนชื่อ view บน production เพื่อแก้สไลด์

6. **3NF/CAP และข้อจำกัดผลวิจัย**
   - raw_value เก็บคู่ amount เพียงอย่างเดียวไม่ได้พิสูจน์ว่าผิด3NF ต้องพิจารณา FD/candidate keys; ข้อความที่ปลอดภัยคือ “ยังไม่ได้พิสูจน์ normal form ครบทุก relation; raw/audit แยกบทบาทจาก typed model”
   - CAP โหนดเดียวไม่มี partition test: ให้เป็นแนวทางออกแบบ ไม่ใช่ผลพิสูจน์ว่าเป็น CP; การเปิด connection ใหม่ไม่เท่ากับผ่าน power-loss durability
   - แผนภูมิ LCA เป็นค่าที่ผู้วิจัยรายงานต่อ1000MJ ไม่ใช่ผลคำนวณทีม; ถ้าพูด BHD/H-FAME ให้คงข้อจำกัด Finnish BHD/pilot H-FAME ไม่อ้างว่าเป็นตัวแทนทุกโรงงานไทย

7. **รูปแบบโปสเตอร์**
