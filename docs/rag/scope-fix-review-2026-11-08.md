# ผลแก้การค้นผิดขอบเขต — 8 พฤศจิกายน 2569

**ประวัติรอบ 4 การ์ด:** ระบบปัจจุบันมี 10 การ์ดและแก้เพิ่มแล้ว ดู [สถานะรับช่วง](../TEAMMATE_NEXT_STEPS_TH.md) ผลด้านล่างเก็บตามรอบ ไม่ใช้แทนผลของโค้ดปัจจุบัน

## สิ่งที่เปลี่ยน

- เพิ่มทะเบียนขอบเขตของการ์ดเดิม 4 ใบใน `retrieval-scope.json` แยกชนิดเชื้อเพลิง สาร ช่วงทดสอบ และการมีค่าปริมาณ ไม่เพิ่มตัวเลขหรือแหล่งอ้างอิงใหม่
- กรองเงื่อนไขที่ผู้ใช้ระบุจากผู้สมัครทุกใบ ก่อนเลือกผลสูงสุด 3 ใบ เงื่อนไขหลายข้อใช้ร่วมกัน เช่น E10 + CO₂ + N₂O ต้องมีหลักฐานรองรับครบในใบเดียว การ์ด E10 cold-start จึงใช้กับ E20/E85, CH₄/N₂O, เครื่องร้อน หรือทั้งรอบไม่ได้
- คำถามขอตัวเลขไม่ใช้การ์ดอธิบายช่องว่างแทนการวัด; คำถามระบุโรงงาน TSM/BBGI/DMF หรือปีที่ต้นแบบไม่มีบริบทเจาะจงจะไม่คืนการ์ด ตัวเลขปีในคำถามอาจเป็นปีเผยแพร่ก็ได้ กฎนี้จึงเลือกปฏิเสธอย่างระมัดระวัง
- เพิ่มคำค้นอีกสำนวนด้วยการแปลง cold start, fuel consumption, carbon dioxide, methane, steam/electricity และคำไทยความหมายเดียวกัน ใช้ cosine สูงสุดจากคำถามเดิมกับสำนวนใหม่โดยไม่เพิ่มคะแนนพิเศษ คง cutoff 0.45 และเวกเตอร์เดิม
- รองรับสูตรสารแบบตัวห้อยและรูป E 20/E-20; แก้การตีความ “CO2 E10” ผิดเป็น CO₂e และ “เกี่ยวข้อง” ผิดเป็นคำถาม “กี่” รักษารูปสระอำภาษาไทยหลัง Unicode normalization
- ตรวจ hash ของ corpus คู่กับทะเบียนขอบเขต หากเพิ่มหรือแก้การ์ดต้องตรวจทะเบียนใหม่ก่อนค้น ป้องกันการใช้กฎเก่ากับข้อความใหม่
- เส้นทาง HTTP และ CLI ใช้ `retrieve` เดียวกัน ผลที่ถูกกรองจะไม่ถูกส่งไปสรุปเป็นคำตอบ; รอบนี้ไม่ได้เรียก Gemini/Cloud

## ผลตรวจจริง

| ชุด | ก่อนแก้ | หลังแก้ |
|---|---|---|
| คำถามเดิมในขอบเขต | 11/12 อันดับแรกถูกและผ่าน cutoff | 12/12 |
| คำถามเดิมไม่มีคำตอบ | ปฏิเสธ 7/8 | 8/8 |
| คำถามเพิ่มในขอบเขต | raw-vector baseline 6/8 | 8/8 |
| คำถามเพิ่มไม่มีคำตอบ | raw-vector baseline ปฏิเสธ 3/18 | 18/18 |

รวมคำถามเดิม 24 และคำถามเพิ่ม 26 = 50 ข้อ มี 46 ข้อที่ให้คะแนนและผ่านทั้งหมด อีก 4 ข้อกำกวมแยกรายงาน ไม่เอามารวมเป็นผลผ่าน คำว่า “คาร์บอน” ยังอาจคืนการ์ดช่องว่างเอทานอล จึงยังต้องอ่านบริบทที่แสดง

การตรวจนี้เป็น **development/regression evaluation** ผู้ช่วยเขียนคำถามก่อนเริ่มแก้ แต่ใช้ผลที่พบมาปรับกฎและคำค้นด้วย จึงไม่ใช่ held-out benchmark หรือการรับรองโดยผู้ใช้จริง ยังต้องใช้คำถามอิสระจากสมาชิกเพิ่ม ผลครอบคลุมการ์ด 4 ใบและชนิดคำที่รู้จัก ไม่ใช่ตัวตรวจความเพียงพอทางความหมายทุกกรณี

- Unit checks 5 tests ผ่าน: คะแนนสูงไม่ข้ามขอบเขต, หลายเชื้อเพลิง, Unicode/ขอบเขตคำ, ข้อความต้นฉบับคงเดิม และ corpus ที่ยังไม่ตรวจถูกปฏิเสธ
- HTTP checks **15/15** ผ่าน รวมคำถามไทยผสมอังกฤษที่เคยพลาด และคำถาม E20, E10/N₂O, E10/hot start คืนรายการว่างพร้อม `summary=null`
- ไม่ได้ตรวจภาพ browser หรือทดสอบ LLM จริงในรอบนี้ ไม่เปลี่ยน production และไม่รันชุด frontend ซ้ำเพราะไม่ได้เปลี่ยนพฤติกรรม frontend รอบนี้

## ตรวจซ้ำ

ให้ใช้หัวข้อ “ประเมินโค้ดปัจจุบันโดยเก็บผลแยกรอบ” ใน [README](README.md) ซึ่งหยุด RAG ก่อนและกำหนด `--output` ในโฟลเดอร์ใหม่ใต้ `build/handoff/rechecks/` ไม่เขียนทับ `evidence/rag-scoped-*.json` ที่รองรับผล 4 การ์ดในรายงานนี้ การประเมินปัจจุบันไม่ใช่การ replay โค้ดรุ่นเก่า

เปิดบริการแล้วตรวจ HTTP อีก terminal:

```powershell
& build/rag-verified-venv/Scripts/python.exe -X utf8 scripts/rag_retrieve.py serve
```

```powershell
python -X utf8 scripts/check_rag_local_http.py
```

ตัวตรวจ HTTP ปัจจุบันตรวจ 10 การ์ดและบันทึก `evidence/rag-expanded-http-2026-11-08.json` ไม่ใช่ไฟล์ HTTP 15 checks ของรอบนี้ หากต้องเก็บผลเครื่องผู้ส่งเดิมให้รันใน checkout แยก ผลเดิมของรอบ 4 การ์ดอยู่ `evidence/rag-scoped-regression-2026-11-08.json`, `evidence/rag-scoped-new-questions-2026-11-08.json`, `evidence/rag-scoped-http-2026-11-08.json`

ขั้นถัดไป: รับคำถามอิสระจากสมาชิกและตรวจคำที่กฎยังไม่รู้จัก ก่อนเพิ่มการ์ดต้องตรวจข้อความ/ที่มา/สิทธิและขอบเขตใหม่ ไม่ถือว่าการผ่านชุดนี้ปิดความเสี่ยงของคำถามทุกแบบ
