## การปรับระบบที่จำเป็น

- สร้าง Qdrant Local collection ใหม่ 10 points/384 มิติ ตาม hash ของ corpus โดยเก็บรุ่นเดิมไว้
- ปรับทะเบียนขอบเขตและผูก hash ใหม่ เพิ่มข้อจำกัดให้คำถามขอตัวเลขจากการ์ดหน่วยหน้าที่/การจัดสรรต้องถามหัวข้อนั้นอย่างชัดเจน ไม่ใช้การ์ดอธิบายฐานแทนค่าเมทานอลที่ยังไม่มี
- เพิ่มคำสำคัญของหัวข้อให้การ์ดใหม่ เช่น การจัดสรรต้องมีคำเกี่ยวกับการจัดสรร/กลีเซอรีน ส่วนการ์ดต้นน้ำต้องมีบริบทปาล์ม/FFB/CPO ช่วยลดการคืนการ์ดที่คล้ายแต่ผิดหัวข้อ
- เพิ่มชื่อหัวข้อสองภาษาเพื่อรองรับ functional unit, allocation, glycerine, data period และ pilot plant โดยคงค่าจากแหล่งต้นฉบับและ cutoff 0.45
- หน้าเว็บแสดงจำนวนการ์ดตาม corpus จริง มีตัวอย่างคำถามใหม่และแสดงผู้เขียน/สิทธิ/ประเภทข้อกล่าวอ้างของการ์ดใหม่ ใช้ textContent สำหรับข้อมูลที่แสดง

รวม 76 คำถาม: 72 ข้อที่ให้คะแนนผ่าน อีก 4 ข้อกำกวมรายงานแยก มี unit tests 6 tests ผ่าน และ HTTP 19 checks ผ่าน รวมคำถามใหม่เกี่ยวกับฐาน, HOLD, allocation และคำถามปริมาณเมทานอลที่ต้องไม่คืนคำตอบ

ชุดใหม่เริ่มรันได้ 13/19 ในขอบเขตและปฏิเสธ 7/7 จากนั้นใช้ข้อที่พลาดปรับชื่อหัวข้อสองภาษาและตัวกรองจนได้ผลข้างต้น จึงเป็น **development/regression tests** ไม่ใช่ held-out benchmark หรือ user study ข้อจำกัดเดิมเรื่องคำถามกำกวมและคำที่กฎไม่รู้จักยังอยู่ ไม่ใช้คะแนนนี้แทนความพร้อมของข้อมูลทั้งโปรเจกต์

ตรวจจริงผ่าน HTTP และข้อมูลดัชนี แต่ไม่ได้ตรวจภาพ browser หรือเรียก Gemini/Qdrant Cloud ไม่ deploy หรือเปลี่ยน MySQL production
