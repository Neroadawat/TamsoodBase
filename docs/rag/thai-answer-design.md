# แนวทางตอบภาษาไทยให้เข้าใจง่าย

## งานที่อ้างอิง

- งานทดลอง RAG สำหรับตอบคำถามคณิตศาสตร์พบว่าคำแนะนำใน prompt มีผลต่อความชอบของผู้ใช้ และคำสั่งที่กำกับคำตอบมากเกินไปอาจไม่ใช่คำตอบที่ผู้ใช้ชอบ งานนี้มีบริบทการเรียนคณิตศาสตร์และกลุ่มตัวอย่างจำกัด จึงใช้เป็นแนวทางเรื่อง “อธิบายพอดี” ไม่ใช่ข้อพิสูจน์ว่ารูปแบบเดียวเหมาะกับทุกคน: [EDM 2024 proceedings](https://educationaldatamining.org/edm2024/proceedings/2024.EDM-short-papers.28/2024.EDM-short-papers.28.pdf).
- งาน Answering with Faithfulness เสนอให้ประเมินว่าคำตอบมีหลักฐานรองรับจริงหรือไม่ ควบคู่กับการสร้างคำตอบ เพราะระบบ RAG ยังตอบผิดจากการค้นหรือการเรียบเรียงได้: [IJCNLP-AACL 2025](https://aclanthology.org/2025.ijcnlp-long.56/).
- คู่มือภาษาง่ายของ WHO และ Style Manual แนะนำให้เขียนถึงผู้อ่านที่ไม่ใช่ผู้เชี่ยวชาญ ใช้ประโยคสั้น อธิบายศัพท์เทคนิค และจัดข้อมูลให้เห็นคำตอบสำคัญก่อน: [WHO](https://www.who.int/about/communications/understandable/plain-language), [Australian Government Style Manual](https://www.stylemanual.gov.au/style-manual-resources/quick-guides/quick-guide-plain-language).

## สิ่งที่เปลี่ยนใน TamsoodBase

- คำตอบตัวเลขยังสร้างจากระเบียนที่ตรวจแล้วในเครื่อง ไม่ส่งให้ Gemini แต่งหรือแปลงตัวเลข
- แยกข้อความอธิบายสำหรับผู้อ่านออกจากข้อมูลต้นทางไว้ใน `thai-answer-copy.json`; ไม่เปลี่ยนค่า หน่วย ปี สถานะ หลักฐาน หรือสิทธิของแหล่งข้อมูล
- เริ่มจากคำตอบโดยตรง แล้วบอกว่าตัวเลขเป็นผลวัด ค่าประเมิน หรือแผนออกแบบ และเพิ่มข้อจำกัดที่จำเป็นต่อการตีความ
- อธิบายคำย่อสำคัญ เช่น CO₂e เป็นคำไทยก่อนใช้หน่วยต้นฉบับ
- ใช้ข้อความ “เอกสารที่ตรวจตอนนี้ยังไม่พบ” เมื่อมีช่องว่าง แทนการสรุปว่าไม่มีข้อมูลอยู่ที่ใดเลย
- หน้าเว็บแสดงคำตอบและลิงก์เอกสารที่ใช้ตอบครั้งเดียว ไม่แสดงการ์ดข้อมูลชุดเดิมซ้ำและไม่โชว์รหัสสถานะภายใน
- Gemini ใช้คำสั่งให้ตอบตรงคำถาม ภาษาธรรมชาติ ประโยคสั้น และแยกผลวัดจากค่าประเมิน; server ตรวจ source IDs และปฏิเสธเลขอารบิก/เลขไทยในคำตอบที่ไม่พบในหลักฐานที่อ้าง โดย normalize comma grouping, เลขไทย และศูนย์นำหน้า/ท้ายทศนิยมด้วยการจัดรูปข้อความ ไม่แปลงเป็น floating-point จึงไม่ยุบจำนวนเต็มขนาดใหญ่ที่ต่างกันให้กลายเป็นค่าเดียว
- ข้อความกำกับ Gemini ระบุชัดว่าคำถามและทุกช่องในหลักฐานที่ค้นได้เป็น “ข้อมูล” ไม่ใช่คำสั่ง เพื่อไม่ทำตามคำสั่งที่อาจฝังอยู่ในคำถาม/เอกสาร พร้อมย้ำให้รักษาหน่วย ช่วงเวลา ฐาน ขอบเขต สถานะ และข้อขัดแย้งตามต้นทาง
- พบคำถามเชิงวิธีคำนวณ CO₂e ถูกจัดเป็นคำถามหาตัวเลขและเคยตอบค่าประมาณโครงการที่ไม่ตรงคำถาม; เพิ่ม intent route ที่แน่นอนและคำตอบผ่านการตรวจซึ่งอ้าง GHG Protocol Product Life Cycle Standard sections 8.3.4–8.3.5 (ข้อมูลกิจกรรม × ตัวคูณการปล่อย) และ IPCC SR15 Glossary (มวลก๊าซ × GWP ตามช่วงเวลา). ไม่คำนวณยอดเอทานอลของทีมและย้ำว่าข้อมูลยังไม่พอ

## การตรวจและข้อจำกัด

`scripts/evaluate_rag.py` ตรวจในชุดคำถามที่เขียนมือว่าเลือก fact ถูก รักษาตัวเลขเดิม ไม่ปล่อยรหัสสถานะ/ชื่อช่องข้อมูลภายใน ตอบวิธี CO₂e ด้วยแหล่งอ้างอิงทั้งสอง และปฏิเสธคำถามนอกขอบเขต ชุดนี้เป็น regression check ขนาดเล็ก ไม่ใช่การทดสอบความเข้าใจของผู้ใช้จริงหรือการรับรองว่า LLM ไม่ผิดพลาด ไม่มีการเรียก Gemini จริงในงานนี้; จึงยังไม่ได้ประเมินสำนวนที่โมเดลสร้างแบบสด

`tests/rag-vercel-api.cjs` ตรวจคำกำกับและ parser: ค่าที่ปรากฏเป็นตัวเลขในคำตอบต้องพบในเนื้อหา/locator/attribution ของแหล่งที่อ้าง; เลขไทย, comma grouping และรูปทศนิยมเทียบกันโดยไม่ใช้ floating-point. Regression test ป้องกันจำนวนเต็มใหญ่ที่ต่างกันแต่ JavaScript ปัดเป็นค่าเดียวกัน. Guard นี้เป็นเพียงการเทียบ token ไม่ได้ตรวจว่าเลขตอบตัวชี้วัดเดียวกัน หน่วยเดียวกัน หรือมีความสัมพันธ์เชิงเหตุผลถูกต้อง และตรวจไม่ครอบคลุมจำนวนที่เขียนเป็นคำ. การทดสอบไม่พิสูจน์ว่าโมเดลปฏิบัติตาม prompt ทุกครั้ง; ยังต้องมี adversarial answer evaluation และผู้ตรวจภาษาไทยก่อนเปิดใช้จริง

ประโยคภาษาไทยในไฟล์ copy เป็นคำอธิบายประกอบที่ทีมเรียบเรียง ไม่ใช่ข้อความอ้างตรงจากเอกสาร ทุกคำตอบยังแนบทางไปยังเอกสารและตำแหน่งที่ตรวจสอบได้.
