Q1 FAME ใช้ INPUT อะไรบ้าง? 8 = 8 SELECT ie.flow, o.amount, o.unit_code FROM inventory_exchange ie JOIN observation o USING (snapshot_id, observation_id) WHERE ie.process_id='FAME' AND ie.direction='INPUT'; MATCH (p:Process {name:'FAME'})-[:HAS_EXCHANGE]->(e:Exchange)-[:OF_FLOW]->(f:Flow) WHERE e.direction='INPUT' RETURN f.name, e.amount, e.unit
Q2 นับ INPUT/OUTPUT ต่อกระบวนการ 8/2 · 5/1 SELECT process_id, direction, COUNT(*) FROM inventory_exchange GROUP BY process_id, direction; MATCH (p:Process)-[:HAS_EXCHANGE]->(e:Exchange) RETURN p.name, e.direction, count(e)
Q3 ค่านี้มาจากบทความไหน? (ตัวอย่าง) ต้อง JOIN ไปตารางแหล่ง/ใช้ source_id ของ observation (หลายตาราง) MATCH (e:Exchange)-[:FROM_SOURCE]->(s:Source) RETURN e.id, s.doi

7ACID vs CAPผลทดสอบ lab · MySQL 8.1 InnoDB

ACID ที่ทดสอบแล้ว

  • A ROLLBACK คืนทั้งชุดคำสั่ง
  • C CHECK/FK กันค่าผิด (3819)
  • I ไม่เกิด dirty read (READ COMMITTED) · snapshot คงที่ (REPEATABLE READ) · แถวที่ล็อกกันเขียนทับ (1205)
  • D COMMIT ยังอยู่เมื่อต่อใหม่

CAP ของระบบเรา

  • โหนดเดียว ไม่มีสำเนา จึงยังไม่ได้ทดสอบ partition
  • แนวทางออกแบบเน้นความสอดคล้อง (ไม่ใช่ผลพิสูจน์ว่าเป็น CP)
  • Neo4j/Qdrant เป็น lab เครื่องเดียว ไม่ใช่ cluster

ยังไม่ทดสอบ: ไฟดับ/รีสตาร์ต · SERIALIZABLE · โหลดจริง

Index + EXPLAIN: ix_period_context ค้นรายงวด 0.21 ms เทียบ table scan 12.0 ms (EXPLAIN ANALYZE · 34,899 แถว · lab)
